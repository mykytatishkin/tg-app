# Управление часовым поясом в приложении

## Обзор

Приложение настроено на работу в часовом поясе **Europe/Vilnius** (UTC+2/UTC+3 в зависимости от летнего времени).

## Как хранится время в базе данных

- **Даты**: хранятся в формате `YYYY-MM-DD` (например, `2024-02-18`)
- **Время**: хранится в формате `HH:MM` или `HH:MM:SS` (например, `14:00`)
- Время в БД интерпретируется как **локальное время Вильнюса**

## Утилиты для работы со временем

Все функции для работы с часовым поясом находятся в `src/shared/timezone.util.ts`:

### `formatDateTimeForNotification(date, time)`
Форматирует дату и время для отображения в уведомлениях.
```typescript
formatDateTimeForNotification('2024-02-18', '14:00')
// Возвращает: "2024-02-18 14:00"
```

### `parseDateTimeInVilnius(date, time)`
Создает объект Date из даты и времени, интерпретируя их как локальное время Вильнюса.
Используется для расчетов (например, сколько минут до записи).
```typescript
const apptDate = parseDateTimeInVilnius('2024-02-18', '14:00');
const minutesUntil = (apptDate.getTime() - Date.now()) / 60000;
```

### `getTodayInVilnius()`
Возвращает текущую дату в формате YYYY-MM-DD по часовому поясу Вильнюса.
```typescript
const today = getTodayInVilnius();
// Возвращает: "2024-02-18"
```

### `getDateInVilnius(daysAhead)`
Возвращает дату через N дней от сегодня в формате YYYY-MM-DD.
```typescript
const in7Days = getDateInVilnius(7);
const yesterday = getDateInVilnius(-1);
```

## Где используется

### 1. Напоминания о записях (`appointments/reminders.service.ts`)
- Форматирование времени в уведомлениях: "🕙Напоминание о записи: 2024-02-18 14:00"
- Расчет времени до записи для определения когда отправить напоминание

### 2. Запросы индивидуального времени (`custom-time-requests/custom-time-requests.service.ts`)
- Уведомления мастеру о новых запросах
- Уведомления клиенту о подтверждении времени
- Проверка что запрошенная дата не в прошлом (используется текущая дата по Вильнюсу)

### 3. Уведомления клиентам (`crm/client-reminders.service.ts`)
- Форматирование доступных слотов: "Пн 18 фев, 14:00"
- Определение текущей даты для фильтрации слотов

### 4. Уведомления через бота (`bot/bot.service.ts`)
- Расчет времени до записи при выборе напитка: "будет через 7 мин"

### 5. API эндпоинты (`appointments/appointments.controller.ts`)
- Получение текущей даты для фильтрации скидочных слотов
- Расчет даты через 60 дней для диапазона слотов

## Резервное копирование

Ежедневное резервное копирование базы данных настроено на выполнение в **00:00 по времени Вильнюса**.

Конфигурация в `.env`:
```
BACKUP_TZ=Europe/Vilnius
```

Используется в `backup/backup.service.ts`:
```typescript
@Cron('0 0 * * *', { timeZone: process.env.BACKUP_TZ ?? undefined })
```

## Важные замечания

1. **Сервер должен быть настроен правильно**: Убедитесь что системное время сервера настроено корректно или используйте NTP.

2. **Расчеты в UTC**: Внутренние расчеты разницы дат (например, для определения стоимости услуги) используют UTC и не требуют изменений.

3. **Перезапуск после изменений**: После изменения `BACKUP_TZ` в `.env` необходимо перезапустить backend для применения изменений.

4. **Летнее время**: JavaScript автоматически обрабатывает переход на летнее время для Europe/Vilnius.

## Миграция с другого часового пояса

Если ранее использовался другой часовой пояс (например, Europe/Kyiv):

1. Обновите `BACKUP_TZ` в `.env`
2. Данные в БД НЕ требуют конвертации, так как они хранятся как "локальное время" без привязки к конкретному часовому поясу
3. Перезапустите backend
4. Все новые уведомления будут использовать новый часовой пояс
